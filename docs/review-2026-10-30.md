# 项目整体审查记录（2026-10-30）

审查结论：项目已经具备账号、连接管理、服务端任务执行、报告、价格管理和打包部署的基础链路，但距离正式的密码分析评测平台还有明显差距。首要缺口是正式评测内容，其次是测评状态、费用口径、PK 配置和公开报告等业务闭环。现有测试通过不等于这些边界已经覆盖。

本次未修改业务代码。审查覆盖 README、启动与打包脚本、Spring Boot 业务层、Vue 页面、数据库迁移、Docker 配置及 CI；另在独立 H2 内存数据库、测试 Agent 和无头 Chrome 中复现关键问题。没有读取或修改日常开发数据库。

优先级：P0 表示对外部署前必须处理；P1 表示正式测评前必须补齐；P2 表示后续产品化和运维完善。标注“代码确认”的条目未宣称完成相应故障注入或生产环境实测。

## 已有基础

- 注册、登录、退出、Cookie 会话、CSRF、资源归属隔离、密码重置与管理员邀请。
- 服务端执行 Agent 协议，支持排队、取消、重试、日志和报告生成。
- Docker 容器资源限制和清理逻辑；报告的服务端验证标记与公开条件。

- 版本化模型价格 API、管理员账号管理、Windows 打包和 CI 工作流。

### F01 · P1 · V4 正式执行与评分未实现【代码确认、API 复现】

`cryptobench-sc-v4` 保持 `executionReady: false`，提交运行得到 HTTP 400“该测评集版本尚未绑定服务端验证器”。目前仅有 Mini-SPN 的 `BenchmarkEvaluator` 实现。材料清单检查脚本只验证材料组织和完整性，不能代替实际评分器。

需要补齐：127 题对应的私有材料、正式输入输出协议、各题验证器、`final_only` / `process_plus_final` 评分、压力题和异常的统计规则、完整验收。材料不足时继续禁止生成正式成绩。

位置：`src/main/resources/static/js/cryptobench-v4.js:21`；`execution/service/TaskCatalogService.java:97`；`docs/v4-materials.md`。

### F06 · P1 · 离开测评页后返回，运行进度可能永久停留【浏览器复现】

需要把活动运行恢复放在统一状态层，按用户和 runId 管理；挂载时重新查询状态并启动轮询，退出/换号清空内存敏感状态。

### F09 · P1 · 价格表没有在运行开始时固定【API 复现】

### F18 · P1/P2 · 远程网站、本机 Agent 与云模型的连接方案不完整【代码确认】

需要明确支持的部署拓扑，提供用户端 Agent 主动连接/任务领取或受控隧道方案；Docker 若需调用云模型，应增加受限推理代理，而非直接取消网络隔离。
